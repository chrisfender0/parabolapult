# Session 1.1 — Repo + GitHub Pages Deploy

## Goal

The scaffold from session 1 is live at `https://chrisfender0.github.io/parabolapult/`, and every future push to `main` redeploys automatically. Getting this working now means every later session ends with a shippable, verifiable build.

## Depends on

Session 1.

## Prerequisites (Chris runs these once on his Mac)

```
brew install gh
gh auth login          # GitHub.com → HTTPS → authenticate in browser
```

## Tasks

- `git init` (branch `main`), initial commit of the scaffold + `plan/`.
- `vite.config.js`: set `base: '/parabolapult/'` with a comment explaining it's a project page, mirroring the memory-card-matching repo.
- `.github/workflows/deploy.yml` — same shape as the memory-card-matching workflow:
  - Triggers on push to `main` plus `workflow_dispatch`.
  - Permissions `contents: read`, `pages: write`, `id-token: write`; concurrency group `pages`.
  - Build job: `actions/checkout@v4` → `actions/setup-node@v4` (node 20, npm cache) → `npm ci` → `npm run build` → `actions/configure-pages@v5` → `actions/upload-pages-artifact@v3` with `path: dist`.
  - Deploy job: `needs: build`, environment `github-pages`, `actions/deploy-pages@v4`.
- Commit `package-lock.json` (required by `npm ci`).
- Create the remote and push: `gh repo create chrisfender0/parabolapult --public --source=. --remote=origin --push`.
- Enable Pages with the Actions source: `gh api -X POST repos/chrisfender0/parabolapult/pages -f build_type=workflow` (or, if that errors because Pages already exists, `-X PUT`). Fall back to the repo's Settings → Pages → Source: GitHub Actions if the API call is rejected.
- Watch the run with `gh run watch` and confirm it goes green.
- Add a placeholder `README.md` (title, one-line description, live link, dev/build commands). It gets fleshed out in session 12.

## Files touched

`vite.config.js`, `.github/workflows/deploy.yml`, `README.md`, `package-lock.json`.

## Done when

`https://chrisfender0.github.io/parabolapult/` loads the wireframe scaffold scene with no 404s on assets (proof the `base` path is right), and the Actions run for the latest `main` commit is green.

## Ask Chris to

Install and authenticate `gh` (commands above) before the session starts, then open the live URL once the deploy is green and confirm it renders.

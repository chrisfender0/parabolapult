# Session 13.1 — Parabolic Mode: Playable

## Goal

Parabolic mode can be played from start to finish: pick the mode and a
difficulty, play 5 rounds by building the equation on an on-screen keypad,
then see results and the leaderboard.

## Depends on

Session 13. Also touches the code from sessions 6, 7, 8, and 9.

## Design notes

### Setup flow

The Setup screen gets a **mode toggle** above the difficulty cards:
`Classic | Parabolic`. Classic is the default, and the last-used mode is
remembered in `localStorage`. The difficulty cards stay the same three ids,
but their descriptions change with the mode:

- Easy: "Factored form: y = x · ( ▢ )"
- Medium: "Standard form: y = −x² + ▢"
- Hard: "Vertex form: y = −( ▢ )² + 36"

`ctx.showScreen('game', { playerName, mode, difficulty })`. `GameSession`
gets a `mode` field (`'classic' | 'parabolic'`). Anywhere that currently
checks `difficulty === 'hard'` to trigger the memorization sequence must
check `mode === 'classic' && difficulty === 'hard'`. **Check every one of
these** (GameController has about eight). Missing one means Parabolic Hard
starts a memorization phase.

### The keypad (why the soft keyboard isn't used)

The answer field is a `<div role="textbox" aria-live="polite">` that sits
inside the blank of the template, with no `<input>` behind it, so the
phone's keyboard never opens. A number pad has no `x`, and a full keyboard
covers half of a 390×844 screen. This also avoids the untested soft-keyboard
problem listed in KNOWN-ISSUES for this mode.

```
 7   8   9   ⌫
 4   5   6   −
 1   2   3   +
 x   0   C   Launch
```

- Keys are at least 44×44 px, use `pointerdown` (so there's no 300ms tap
  delay), and are real `<button>`s.
- Physical keyboard on desktop: `0–9`, `x`, `+`, `-`, Backspace, Escape
  (clear), and Enter (launch).
- Input is limited to 8 characters. Typing `-` shows `−`.
- If `parseLinear` returns `null`, show "Can't read that. Try something like
  12 − x" under the equation. **No try is used** and nothing launches.
- The blank shows a blinking caret when empty. As the player types, the
  expression appears inside the template, so they always see the whole
  equation.

### Controller

Add `submitParabolic(text)` next to `submit()`, with the same guards
(`roundOver`, `flying`):

1. `parseLinear(text)`. If it returns `null`, emit `input:invalid` and stop.
2. `gradeParabolic(equation, parsed)` returns `{ hit, flight }`.
3. Store `{ hit, typed: formatLinear(parsed) }` for this attempt, then
   launch the trajectory that matches `flight.kind`.
4. In `_handleLand`, when `mode === 'parabolic'`, use the stored `hit`, not
   `resolveOutcome()` (see session 13 for why rounding breaks this). The
   rest of the hit/miss/tries/streak code stays shared. History entries also
   store `typed` and `solution`.

Miss feedback text by kind: arc: "Landed at 11.5". dive: "Opens upward.
Straight into the ground". orbit: "No way down, it's still going up".
fizzle: "Never left the pad". overshoot: "Flew past 24".

Same rules as Classic: 3 tries, and the equation and target stay the same
between tries. Keep the text that's already typed after a miss so the player
can fix it instead of retyping everything.

### Scoring and leaderboard

- `scoreRound` takes `mode`. Parabolic multipliers:
  `{ easy: 1.5, medium: 2, hard: 2.5 }`. Parabolic has no speed bonus, so
  Parabolic Hard scores somewhat lower at best than Classic Hard. That's
  acceptable, and Chris can tune it after play-testing.
- Leaderboard entries get a `mode` field. Old entries without one are
  treated as `'classic'`. The Landing table shows the entry label as
  `Easy` for Classic and `Parabolic · Easy` for Parabolic. Keep a single
  shared board.
- Results screen: for Parabolic rounds, show the player's last typed
  expression next to the solution, the same way Classic Hard shows its
  reveal. Example: `you: x − 12   ✓ 12 − x`, with ✓/✗ icons as well as color.

## Tasks

- `src/ui/screens/Setup.js`: mode toggle (a segmented control with
  `aria-pressed`), descriptions that change with the mode, remember the last
  mode, and pass `mode` through.
- `src/game/GameSession.js`: add a `mode` field.
- `src/game/GameController.js`: a generator table keyed by
  `${mode}:${difficulty}`, `submitParabolic`, the `_handleLand` branch, and
  the audit of every hard-mode guard.
- `src/ui/keypad.js` (new): `mountKeypad(root, { onChange, onSubmit })`,
  with `setValue`, `clear`, `setDisabled`, and `unmount`.
- `src/ui/hud.js`: a Parabolic equation panel (template with the blank
  filled in), the keypad instead of the answer input, the invalid-input
  message, and miss text for each flight kind.
- `src/game/Projectile.js` / `src/game/effects.js`: play the dive, orbit,
  and overshoot trajectories. dive should reuse the existing crash
  particles. orbit and overshoot have no landing effect, and `land` fires
  when the animation ends.
- `src/game/scoring.js`, `src/storage/leaderboard.js`,
  `src/ui/screens/Landing.js`, `src/ui/screens/Result.js`: add mode support
  as described above.
- `src/style.css`: keypad layout, and the equation panel at 390×844 so the
  keypad plus the equation never covers the target marker. If it can't fit,
  move the camera framing up.
- `docs/TEST-CHECKLIST.md`: add a Parabolic section and run it (see below).
- `README.md`: add a Modes section with the three templates and one line on
  the rule "lands at the equation's root".

## Done when

- Each Parabolic difficulty plays 5 rounds through to results, and the
  leaderboard entry says `Parabolic · <Difficulty>`.
- These inputs behave as follows with target 12:
  - Easy: `12−x` hit, `-x+12` hit, `x−12` dive, `10−x` lands at 10,
    `−2x+23` lands at 11.5 as a **miss**, `12` orbit, `30−x` overshoot.
  - Medium: `12x` hit, `12` short arc to 3.5, `−12x` fizzle.
  - Hard (c = 36): `x−6` hit, `6−x` hit, `x−10` arc to 16, `x−20`
    overshoot (roots 14 and 26), `x+6` fizzle.
- Input that can't be parsed never uses a try.
- Classic Easy, Medium, and Hard, including the memorization sequence, still
  play the same as before.
- At 390×844, the keypad, the full equation, and the target marker are all
  visible at once, and the phone keyboard never opens.
- Old leaderboard entries (no `mode`) still show up correctly.
